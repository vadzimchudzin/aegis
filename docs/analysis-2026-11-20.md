## 1. Что это такое

Десктопный терминал для торговли золотом (XAUUSD) с ИИ‑наблюдателем: `Tauri 2` (Rust) + ванильный HTML/JS UI + Python‑мост к MetaTrader 5. Три источника данных — Binance USDⓈ‑M `XAUUSDT`, Bybit USDT‑перп `XAUUSDT`, RoboForex MT5 `XAUUSD`; можно держать подключёнными все три одновременно, но график всегда показывает только один — данные площадок не смешиваются.

Режимы наблюдателя: **paper** (симуляция) и **money** (реальные ордера через MT5). README прямо требует приёмки на демо‑счёте Windows до клиентского или реального использования.

## 3. Архитектура: кто что делает

```
app/ui/*.js  ──invoke──▶  app/src-tauri/src/*_cmd.rs  ──▶  aegis-core
                                                              ├─ broker.rs  (enum Connector: Binance | Bybit | Roboforex)
                                                              ├─ binance.rs / bybit.rs  — REST + HMAC, книги, сделки
                                                              ├─ mt5.rs     — JSON‑IPC в python‑мост
                                                              ├─ observer.rs— snapshot → prompt → validate → paper/money
                                                              ├─ ai.rs / ai_provider.rs / local_ai.rs — Qwen локально, OpenRouter
                                                              ├─ bounce/*   — уровни, метрики касаний, модель вероятности, GA, бэктест
                                                              └─ event_*    — журнал событий, телеметрия, инструменты
                                                                     │
                                                            python/aegis_lab/bridges/mt5_bridge.py
                                                              └─ MetaTrader5: риск‑гейты + order_send + trade ledger
```

Ключевое решение: **вся арифметика риска живёт в Python‑мосте рядом с `order_send`**, Rust только передаёт `TradeRequest`. Это правильно — проверка и отправка в одном процессе, без окна, в котором состояние может измениться.

## 4. Что сделано сильно (проверено в коде)

1. **Идемпотентность ордеров — crash‑safe.** `mt5_bridge.py:_run_once_locked` пишет запись `pending` в ledger **до** отправки, под файловой блокировкой (`fcntl`/`msvcrt`), атомарной записью. Если процесс умер между записью и ответом, запись остаётся `pending` и при повторе превращается в `unknown`, а **любой новый `open:` блокируется, пока есть `pending`/`unknown`**. Параметры запроса хешируются: повтор с тем же `request_id`, но другими числами — отказ.
2. **Риск‑гейты перед отправкой** (`mt5_bridge.py:place_order`): `confirm_real=true` обязателен; `0 < risk_pct ≤ 1 %`; дневной лимит `≤ 10 %`; свежесть котировки (старая > 10 с, будущая > 2 с — отказ); спред ≤ `max_spread`; соблюдение брокерского `stops_level`; netting‑счёт с позицией → отказ; чужая позиция (не наш `magic`) → отказ; лимит числа позиций; агрегатная экспозиция ≤ 10× equity и суммарный риск ≤ 5 %; **пересчёт всех проверок ещё раз перед `order_send`**; если объём риска ниже минимального лота — отказ, а не округление риска вверх.
3. **Money‑путь в Rust не доверяет ничему** (`observer_cmd.rs:execute_money`): сверка `login+server` счёта перед исполнением, проверка эпохи (сессия остановлена → отмена), для управления позицией — `ticket` + `magic=26070552` + `XAUUSD`, иначе отказ.
4. **Журнал решений** (`observer.rs:rotate`): читает файл целиком, парсит каждую строку, при повреждении **отказывается** ротировать; сохраняет все незавершённые `broker_intent`; переносит свежие ~4 MiB; архив zstd проверяется SHA‑256 до замены; замена атомарная. Ротация на 24 MiB, жёсткий предел 32 MiB.
5. **CI как реальный гейт** (`.github/workflows/ci.yml`): `cargo fmt --check`, `cargo clippy --all-targets -D warnings`, `cargo test --workspace`, `npm test`, `python -m unittest`; затем Windows‑job с тестами и сборкой NSIS. Релизный workflow привязывает тег к протестированному SHA и удаляет черновик, привязанный к другому коммиту.
6. **Документация по каждой бете** с разделом Verification и честными формулировками о непроверенном (например beta.11: «Live RoboForex demo acceptance on Windows is still required»).
7. **Тестов ~220 в Rust** + python‑сьют с `fake_mt5` + node‑тесты UI; есть тесты именно на опасные места (идемпотентность, ротация, часы MT5, отказ при чужой позиции).

### P2 — продукт

- **Money‑режим не подтверждён на живом/демо счёте.** Это единственный, но решающий незакрытый пункт перед реальными деньгами: логика выглядит защищённой, но ни один отчёт не подтверждает прогон на RoboForex demo. Всё остальное — бумага и фикстуры.
- **Стратегии Breakout, Liquidity Sweep, DATA — заглушки**, `bounce` по собственным документам без эджа. То есть продукт пока не имеет статистически подтверждённой стратегии; ценность сейчас — инфраструктура и наблюдатель.
- **Три параллельных механизма перевода** (`i18n-dict.js`, локальный `DICT` в `local-ai.js`, `structural-i18n.js`, плюс `words` в `densities.js`) и **ни одного теста на полноту перевода**. Полноту я проверил вручную: ru/kk совпадают (69/69 в `local-ai`, 35×3 в structural, паритет в densities) — дыр нет. Но ключ перевода — **английский текст**, поэтому любая правка формулировки молча снимает перевод. Один общий словарь + тест на паритет закрыли бы класс ошибок.

### P3 — техдолг

- `observer.rs` 2 493 строки, `health_cmd.rs` 1 542, `observer_cmd.rs` 1 651 — читаются тяжело, кандидаты на разбиение по подсистемам.
- `Journal::new` отказывается открывать файл > 32 MiB («journal exceeds the 32 MiB limit»). Для файлов старого формата это осознанный fail‑closed, и `rotate()` вызывается раньше, так что практического риска нет — но стоит теста «файл ровно на пределе».
- `docs/audit-local-ai-2026-10-08.md` и `docs/two-ai-verification.md` — исторические аудиты; часть их выводов уже закрыта, часть нет. Нужен статус у каждого пункта.
